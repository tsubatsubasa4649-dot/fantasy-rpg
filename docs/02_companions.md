# フェーズ1 — 仲間システム設計（提案 v0.1）

## 基本仕様
- **戦闘パーティ最大4人**（主人公＋仲間3人）。加入済みの控えは拠点で交換、特定イベントはフィールドでも編成変更を許可。
- 仲間は**固定ロール**で主人公のみジョブチェンジ。仲間の強さはレベル・装備・固有アビリティ・信頼度で変わる。
- 20人以上を実装前提として、キャラクターID、加入条件、条件失効、相互関係、イベント参照、離脱、復帰、時期差分を全てデータで定義。
- 加入状態は unavailable / met / recruitable / recruited / reserve / departed / dead_or_missing の列挙値と、永続フラグ群を別に保持する。「見つけた」≠「加入した」。
- 同じキャラの二重加入を防ぐ。時期限定仲間は**加入期限を過ぎる前に手掛かりを複数回提示**。期限が切れても噂や遺品は残す。

## 宣言的な条件表現
各条件は AND / OR / NOT と事実型述語で表現。例：

```json
{
  "all": [
    {"party_recruited": "ch_meri"},
    {"party_recruited": "ch_ricky"},
    {"party_active": "ch_meri"},
    {"world_phase_gte": 2},
    {"flag_is": ["bridge_repaired", true]}
  ]
}
```

※ `party_recruited` は控えを含む加入済み、`party_active` は戦闘編成中を指す。`flag_is` はプレイヤーの進行状態を参照。成立しない理由は個別に人間向けログ化できる。

## 関係性
関係は有向／無向のタグ付きグラフで表現（siblings, rivals, mentor, hidden_identity, owes_debt など）。関係ごとに「最初から公開／会話で判明／終盤で公開」を指定。物語ラインは一般に「関係者2〜3人が加入済み、うち必須同行1人＋時期条件＋トリガー」で開始できる。例外として未加入NPCの関係性ルートも許可。

**見逃しを理不尽にしないルール**：関係者全員を常時パーティに入れる要求は原則禁止。加入済み判定は控えを含む。必須同行はイベントに入る直前の1人程度に留める。失効期限は日誌に婉曲に表示し、回避分岐も用意。

## 実装上の分離
- `characters.json` に固有情報・初期ステータス・役割・画像参照・加入イベントID。
- `relations.json` に関係グラフ、公開段階、発見フラグ。
- `events.json` に加入/離脱/時期変化の条件と効果。
- `storylines.json` に大型ラインの段階と進行条件。
- `save` に加入状態、編成4人、個別状態、発見履歴を格納。マスターデータはセーブへコピーせずID参照。
