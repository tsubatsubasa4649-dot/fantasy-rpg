# フェーズ3.5 — 実機フィードバックを反映した素材・BGM改修

## 目的
「スライムに対して人間が小さい」「仲間の画像が全員同じ」「マップ・戦闘の見栄えが仮」「Godot版に曲がない」を改善する。既存HTML版は変更しない。

## 反映済みの仕組み
- **戦闘立ち絵表示**：余白を透明度から自動トリムし、人間を最大4人の2×2配置にする。スライムだけが不釣り合いに巨大にならない倍率へ修正。
- **新規生成画像からの切り出し**：4人（主人公・リッキー・メリル・ゴロー）×探索／戦闘の8種類を、チャットで生成した独自の16-bit風イラストから選んで1枚の小型PNGアトラスにまとめた。元の大型生成イラスト全体はゲームで使用しない。
- **画像をコードで描かない**：Pillowは画像のトリム・縮小・パレット化のみ。GodotのGDScriptはPNGのデコード、切り出し、表示と移動・被弾演出を行う。描き直しは画像生成側で行う。
- **データ駆動**：`characters.json` の `field_sprite_id`, `battle_sprite_id` でキャラ別の素材を指定し、マップ側の `points[].image` でNPC表示画像を指定。
- **歩行の演出基盤**：移動時の上下の軽い揺れ、右向き時の水平反転に対応。**現状は真正な4方向3コマ歩行素材ではない**。背面と左右の専用素材ができたら、アトラス定義とアニメフレーム参照を追加する予定。
- **戦闘演出**：行動解決時の敵の被弾フラッシュ。技種別のエフェクトや実モーション（攻撃・被弾・戦闘不能）は今後。
- **BGM**：`tools/build_audio.py` が外部音源や既存曲のフレーズを使わない、オリジナルのフィールド・洞窟・通常戦闘曲を合成し、依存ライブラリ不要のWAVファイルとして書き出す。GodotのWebビルドに含め、地域／戦闘開始／勝利で自動切替。メニューに音楽ON/OFFを追加。

## アートアトラスの形式
- 元画像は生成PNG、保存先は `godot/assets/party_sheet.b64`（PNGのBase64テキスト）。
- デコードサイズ：160×104 px、4列。
- 列順：hero / ricky / meri / goro
- 上段：探索表示 `Rect2i(index*40, 0, 40, 40)`
- 下段：戦闘表示 `Rect2i(index*40, 40, 40, 64)`
- 各セルの透過余白はロード時にトリム。アトラスを差し替えるだけで解像度を維持できる。
- この画像は**新キャラの最終デザインではなく、見た目を分けるための暫定版**。リッキー（剣士）が魔法使い風など、キャラ設定との整合は本制作用の画像を生成し直して調整する。

## 運用と品質基準
- 既存のGitHub ActionsがGodot 4.3をヘッドレス実行し、フェーズ2・3と画面テストを実行してからWebビルドを公開。
- WebAudioのブラウザ版と、WAVで流れるGodot版は**別の音源実装**。
- 自動テストでは全WAV音源の存在、キャラ画像読み込み、戦闘画面、画面内の配置を検証する。Safari実機の最終確認はユーザーのプレイで行う。
- チャット内で「次の日に完了する」等の作業予約はできない。作業のGitHubへの反映・CI成功は実際に確認できた場合だけ報告する。

## 次の本制作アートタスク
1. 正面／背面／左／右 × 各3フレームの歩行アトラスを4人分、同じ素体サイズで生成。
2. 戦闘立ち・攻撃・技・被弾・戦闘不能の5〜6ポーズを別アトラスにする。
3. 草原・村・洞窟の地形は32×32のタイルシートとして、道・崖・木・水・建造物を同一パレットで作る。
4. バトル背景は左右2段構図、足元ライン共通、味方の画素縦サイズを敵スライムの1.3〜1.8倍程度に保つ。
5. 音楽はテンポだけでなく調性・モチーフで「時期1→2→3」の変化を表現。現在の3曲は試作音源。
